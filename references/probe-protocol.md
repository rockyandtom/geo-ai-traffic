# GEO 探测执行细则（SKILL.md §6 依据）

本文件是 `SKILL.md` §6 的展开。目的只有一个：**把"AI 有没有推荐我"变成能对比、能复盘的数字**，而不是"我问了一下，好像提到了"。

---

## 1. 问题库怎么出（五档，每语言一套）

主体永远是**第二档（找工具题）**，其余四档是校验与补充。出题前先有输入三件套里的 `keyword`。

### 1.1 五档定义与建议数量

1. **品牌题（建议 2–4 题）**：直接问品牌名/域名。
   - 作用：它认不认识你；描述是否过时（价格、免费额度、功能列表）。
   - 例：`What is <brand>?` / `Is <domain> legit?` / `How much does <brand> cost?`
   - 判读：不认识＝还没进它的检索范围；认识但价格写错＝它抓到的页面是旧的，回去改页面并等重抓。
2. **找工具题（主体，建议 10–15 题）**：每个细分品类一题，问"有没有能做某事的网站/工具"。
   - 这是唯一稳定触发联网搜索 + 引用来源的题型（见 SKILL.md §1 第 1 条）。
   - 例：`Is there a website that can turn a photo into a poster?` / `What tool can generate <X> for free?`
   - 出题方式：把主词拆成细分场景（用途 × 对象 × 免费/无水印/批量），一个细分一题。**不要用行业术语**，用用户嘴里的说法。
3. **比较 / 合集题（建议 3–5 题）**：`What are the best <category> tools in 2026?` / `Which tool can do A and B in one place?`
   - 作用：看它在"榜单型"回答里给不给你位次 —— 这是最容易被引用的位置。
4. **口语版（建议 2–3 题）**：同一需求换日常说法再问一遍。
   - 例：`I need something to make a cool poster for my event, any site?`
   - 作用：检验"术语版被提到、口语版没被提到"这类落差 —— 落差大说明你的页面措辞离真实用户太远。
5. **解释类题（建议 1–3 题，不要多）**：`What is <concept>?` / `How does <technique> work?`
   - 作用：只用来验证"解释类问题不联网"这条规律是否还成立。**不要指望在这类题里被提到。**
   - 如果某天解释类题开始联网引源了，说明规则变了，整个打法要重估。

### 1.2 多语言

每种目标语言**各出一套完整五档**，不要只翻一档。非英语市场里，用户问法和英文完全不同，直接机翻会得到没人这么说话的问题。

### 1.3 落表

填 `assets/templates/question-bank.csv`，字段：`qid, tier, lang, question, note`。
`tier` 用固定值：`brand` / `tool` / `compare` / `spoken` / `explain`。

## 2. 提问规程（机械细节直接决定数据可信度）

1. **每个问题新开会话。** 同一会话里连着问，后一题会被前一题的上下文污染。
2. **页面打开后等三四秒再输入**，否则输入可能丢字符。
3. **确认消息真的发出去了**（看气泡出现），别对着空输入框等。
4. **判断"写完"的标准：回答十几秒不再变化。** 最长等两分钟；两分钟还在变就再等，不要中途截图当结论。
5. **存三样**：回答全文、整屏截图、点开「来源 / Sources」面板后的截图或列表。来源面板才是"它引用了你哪一页"的证据。
6. **两题之间隔二三十秒**，避免触发限流。
7. **遇人机验证 / 限流 / 要求登录：立刻停下，记录当时的题号与环境，不硬闯。** 硬闯会把账号打进风控，后面整批数据都作废。
8. **同一问题问三遍。** 每次的名单和顺序都会变，单次结果不能当结论。三遍都不提＝稳定不提；三遍里提一次＝边缘，需要在报告里标出来。
9. 探测时**记下开始与结束时间**，后面要和服务器日志对照（见 §6.1）。

## 3. 记录字段（每条回答一行）

`assets/templates/probe-log.csv` 的列，逐项含义：

1. `qid` —— 对应问题库的编号。
2. `tier` —— 题型：`brand` / `tool` / `compare` / `spoken` / `explain`，从问题库带过来，汇总脚本按它分组。
3. `question` —— 实际问出去的原文（含你临时改过的措辞）。
4. `lang` —— 语言。
5. `env` —— `anon`（未登录）/ `logged`（登录后临时聊天）。
6. `round` —— 第几遍（1/2/3）。
7. `searched` —— 是否触发联网搜索：`yes` / `no` / `unsure`（unsure 要写理由）。
8. `mentioned` —— 提没提你：`yes` / `no`。
9. `rank` —— 提及位次（第几个被点名，1 起；没提留空）。
10. `quote` —— 提到你时的原话，逐字抄（含引号时整格加双引号）。
11. `cited_url` —— 引用的是你哪一页：`home` / 具体内页路径 / `none`。
12. `outdated` —— 描述是否过时：`no` / `price` / `feature` / `other`，过时处写在 `note`。
13. `does_it_for_you` —— 它有没有说「我直接在对话里帮你做」：`yes` / `no`。**这一列是在算它抢了你多少用户。**
14. `competitors` —— 它点名的其他网站，分号分隔，原样抄域名。
15. `screenshot` —— 截图文件名。
16. `note` —— 异常、限流、可疑点。

### 3.1 为什么 `cited_url` 和 `does_it_for_you` 不能省

1. `cited_url` 区分"引首页"和"引内页"。只引首页说明你的落地页还没被当成这个需求的答案页 —— SKILL.md §2 第 2 条的"一需求一页"没做到。
2. `does_it_for_you` 是唯一能直接量出"AI 自己在做这件事、不需要点进网站"的比例。这个比例高，说明这个需求**天生不适合做站**，早点换需求比优化页面划算。

## 4. 两种环境分开统计，绝不能混算

同一批 17 题实测：**未登录提到 2 次、登录后 5 次。** 差 2.5 倍，混在一起就无法判断是变好了还是换了环境。

1. **未登录（anon）**：脚本开全新浏览器、每题新会话。
   - 优点：最干净、可无人值守、可重复。
   - 特点：结果偏保守（没有账号画像加持），适合做长期趋势线。
2. **登录后临时聊天（logged）**：更贴近真实用户。
   - **必须用临时聊天 / 无记忆会话**：否则账号里关于你自己产品的历史记忆会污染结果，你会得到"它很了解我"的假象。
   - 不能无人值守（要人工过验证）。

报告里两种环境**分两段写**，各自给提到率，不要给一个"总提到率"。

---

## 5. 判读口径

1. **提到率** = `mentioned=yes` 的行数 / 该组总行数。按 `tier` 和 `env` 分别算。
2. **联网率** = `searched=yes` / 总行数。`explain` 档的联网率应该接近 0；如果 `tool` 档联网率也低，说明你问的题不像"找工具"，回去改题。
3. **平均位次**：只对 `mentioned=yes` 的行算 `rank` 均值。位次从 5 掉到 2 比"从没提到变成偶尔提到"更有价值。
4. **三遍一致性**：三遍全提 / 三遍全不提 / 摇摆。摇摆的题单独列出，不要平均掉。
5. **竞品榜**：把 `competitors` 列按域名拆分计数，取前 10。这就是你实际在跟谁抢引用位 —— 比关键词工具算出来的竞品更真实。
6. **抢用户比例** = `does_it_for_you=yes` / 总行数。

`scripts/summarize_probe.py` 会直接算 1/2/3/5/6。

## 6. 对账：用自有数据交叉验证

### 6.1 服务器日志

1. **把两类抓取分开数**：
   - 索引爬虫（定期来、抓全站、UA 是 `GPTBot` / `OAI-SearchBot` / `ClaudeBot` 等）。
   - 用户对话时的实时抓取（`ChatGPT-User` / `PerplexityBot` 这类，通常跟着某次提问来、只抓一两页、时间点分散）。
2. **剔除噪声**：冒充扫描器（UA 对但 IP 段不对、请求模式像扫描）、页面预加载/预览产生的碎片请求（favicon、og 图、只有 HEAD 没有 GET）。
3. **探测时段单独标注**：你自己去提问会引来它抓你的页面。探测开始到结束后一段时间内的抓取，**不能算进自然抓取量**，否则会得出"GEO 起效了"的假结论。

### 6.2 外部数据只当参照，不当判定

1. 不要只盯 `chatgpt.com` 这条引荐。**`direct` 里可能藏着 ChatGPT 流量**（也混着爬虫），单看引荐来源会系统性低估；统计工具只会识别出 chatgpt.com 一个来源，所以**必须自己埋点记来源**（动作表第 13 行，做法见 SKILL.md §3.1 与 `geo_attribution.py`），外部工具的数据只当参照、不当判定。要看 chatgpt / gemini / perplexity 的构成与走势，不看单日绝对值。
2. 工具里的 AI 引荐口径是**快照，滞后数天到数周**。今天改了页面、明天没变化属正常，别拿它当"改了没用"的证据。
3. 收录与出词用 GSC：属性要加**域名**（Domain property）而不是单个网址，新站验证等 **24–48 小时**；取数见 skill `gsc-query`。这两项只用来回答"卡在哪一环"，不用于评价页面质量。

### 6.3 判失败的正确顺序

**先收录 → 再出词 → 再引荐。** 引荐为 0 时按这个顺序倒查：
1. 页面收录了吗（GSC 索引状态）？
2. 主词出词了吗（GSC 查询词里有没有主词）？
3. 有出词没引荐 → 才轮到查代码：robots / 边缘层拦截 / **SSR 与 FAQ**（跑一次 `geo_audit.py` 把这几项一起看）。

## 7. 常见误判（踩过的坑）

1. **只问一遍就下结论**：单次名单和顺序都会变，必须三遍。
2. **登录态开正常会话**：账号记忆污染，得到虚高的提到率。必须临时聊天。
3. **把"解释类题没提我"当失败**：那类题本来就不联网、不引源。
4. **把探测引来的抓取当自然增长**：探测时段必须标出并剔除。
5. **只看 chatgpt.com 引荐**：`direct` 里可能有一半。解法不是换一个统计工具，而是自建归因埋点（SKILL.md §3.1）；referrer 为空的标 `direct_suspect_ai` 单独算，别并进确定的 AI 来源。
6. **刚改完就看数据**：AI 引荐快照滞后数天到数周，GSC 也要 24–48 小时。
7. **被限流后继续硬问**：数据全废，还可能把账号打进风控。
8. **用 DR 判断能不能被推荐**（2026-09-10，13 群）：1 DR 的站也被 ChatGPT 推荐过，哥飞确认「谷歌和 ChatGPT 都不看 DR」。DR 只影响你怎么做外链，不影响 AI 提不提你。
9. **把"没写 llms.txt"当引荐为 0 的原因**（2026-09-13，7 群）：谷歌明确说不看这个。真正的堵点在边缘层拦截与前端渲染，`geo_audit.py` 的 SSR / GPTBot 两项才是要先查的。
10. **用单日量判断成败**（2026-09-29）：有站每天 10 来个 GPT 用户，「一过 0 点直接变 0」。→ 看 7 日曲线与三遍探测的一致性，不看单日。

## 8. 一轮探测的产出物清单

1. `question-bank.csv`（本语言、本环境用的那一版）
2. `probe-log.csv`（每行一条回答，九项齐）
3. `screenshots/`（整屏 + 来源面板）
4. `summarize_probe.py` 的输出（提到率 / 联网率 / 平均位次 / 竞品榜 / 抢用户比例）
5. `geo-source-log.csv` 与 `geo_attribution.py report` 的输出（各来源会话 / 注册 / 付费、注册到付费转化率、chatgpt.com 单条能认出的量 vs 自埋点认出的 AI 总量、direct 疑似量占比）—— 这是探测数据之外的另一半证据，见 SKILL.md §3.1
6. 一段结论：现在卡在**收录 / 出词 / 引荐**哪一环，下一步做哪一件事。
